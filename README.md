## Engineering Standard

I approach every system with the same question: *what would it take for this to be a product?*

That means documentation written for strangers, not teammates. APIs designed for developers, not just internal use. Packaging that installs cleanly. Architecture that survives a year of changes. A user experience that does not require explanation.

Technical depth earns nothing if the system cannot be used, understood, or extended by someone who was not in the room when it was built.
